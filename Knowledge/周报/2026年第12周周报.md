#### 2. Lumos 工程限制深度分析（3月24日）

**问题发现**：
在使用 lumos AI 问答服务时，发现系统存在不合理的前置约束问题

**典型问题**：
- **现象**："问问题前系统先判断表和问题无关然后告诉你"
- **根本原因**：工程侧为防止 LLM 胡乱关联表，设置了相关性过滤机制
- **问题本质**：阈值过激 + 将过滤结果暴露给用户，导致体验不佳

**改进建议**：
1. **静默降级**：相关性低时不直接拒绝，而是降低表的优先级
2. **用户自主权**：允许用户手动指定要查询的表
3. **优化阈值**：调整相关性判断阈值，减少误判

**影响范围**：
- 当前 lumos 系统用户体验
- 数据分析 Agent 的查询准确性
- 与 menglong 沟通："lumos 工程起起来很费劲"

### 技术调研与学习

#### 1. Knot 平台能力调研（3月24日）

**调研问题**：Knot 能否搜索公司内网其他系统？

**调研结论**：
Knot 提供三种与外部系统集成的方式：

1. **知识库集成**：
   - 将外部系统数据导入 Knot 知识库
   - 适用于文档类数据（iwiki、KM 等）
   - 优点：检索速度快，支持语义检索

2. **MCP Tools 集成**：
   - 通过 MCP 协议调用外部系统 API
   - 适用于动态数据查询（灯塔、TAPD 等）
   - 优点：实时数据，无需数据导入

3. **浏览器工具集成**：
   - 通过浏览器自动化访问外部系统
   - 适用于无 API 的系统
   - 限制：需要鉴权和登录态

**技术价值**：
- 明确了 Knot 的集成能力边界
- 为后续平台选型提供参考

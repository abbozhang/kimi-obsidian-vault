# 🌙 KimiVault 知识库设计

> 为「小想法 + 人生感悟 + 收藏材料」设计的简单体系

---

## 核心原则

**不要追求完美分类，要追求「写的时候不纠结」**

Obsidian 的强大在于链接，不是文件夹。先扔进去，再慢慢长出来结构。

---

## 你的三类内容 + 对应入口

### 1️⃣ 小想法（工作/兴趣相关）

**特点**：随时蹦出来，主题杂（AI、Vlog、产品...）

**做法**：
- 先全部扔进 `💡 Inbox/想法/` 
- 命名随意：`AI-Agent-对话模式.md`、`Vlog-开头怎么吸引人.md`
- 每周花 10 分钟整理，把相关的连起来

**示例结构**：
```
💡 Inbox/想法/
├── AI/
│   ├── Agent-倾听模式.md
│   └── 对话资产-保存思路.md
├── Vlog/
│   └── 开头钩子-3秒定律.md
└── 产品-Tomoro/
    └── 功能方向-社区讨论.md
```

---

### 2️⃣ 人生感悟（碎碎念、成长、规划）

**特点**：私人、时间线强、需要回顾

**做法**：
- **每日感悟** → 直接写在 `📓 Daily/YYYY-MM-DD.md`
- **月度规划** → `🌱 成长/规划/2025-02-月度.md`
- **年度规划** → `🌱 成长/规划/2025-年度.md`
- **随机碎碎念** → `🌱 成长/随想/随便起个名字.md`

**关键**：这类内容用「时间 + 主题」双维度管理

---

### 3️⃣ 收藏材料（文章、网站、没读完的内容）

**特点**：来源杂、读不完、容易吃灰

**做法**：
- **第一步**：`📚 材料/待读/小红书-文章标题.md`
- **第二步**：读完后移到 `📚 材料/已读/`，并写 3 句话总结
- **第三步**：把总结链接到相关「想法」或「项目」

**解决吃灰问题**：
- 每周五弹出「待读清单」提醒
- 读不完就删，没损失

## 简单概念解释

### 「数据库」在 Obsidian 里是什么？

**不是真的数据库**，就两种形式：

1. **Dataview 插件**（进阶）
   - 自动汇总，比如「显示所有标了 #待办 的笔记」
   - 你现在不需要

2. **MOC（Map of Content）**（推荐先用这个）
   - 就是一个普通笔记，手动整理链接
   - 比如 `MOC/AI-想法汇总.md` 里列所有 AI 相关的想法链接

### 链接怎么玩？

```markdown
我在 [[AI-Agent-对话模式]] 里提到了倾听问题，
这和 [[Vlog-开头怎么吸引人]] 里的「给用户思考时间」是一个道理。
```

Obsidian 会自动识别 `[[笔记名]]`，点击就能跳转。

## 推荐起步结构

```
KimiVault/
├── 📓 Daily/                    # 每日笔记（自动生成）
├── 💡 Inbox/                    # 所有新想法先扔这里
│   ├── 想法/                    # 工作/兴趣相关
│   └── 材料/                    # 待读的文章
├── 🌱 成长/                     # 人生感悟、规划
│   ├── 规划/                    # 年度/月度
│   └── 随想/                    # 碎碎念
├── 📚 材料/                     # 收藏的内容
│   ├── 待读/
│   └── 已读/
├── 🏷️ MOC/                      # 索引页（手动整理）
│   ├── AI-想法汇总.md
│   ├── 产品-Tomoro-方向.md
│   └── 个人成长-轨迹.md
└── 🖼️ Attachments/              # 图片附件
```

## 使用流程（一天下来）

| 场景 | 操作 |
|------|------|
| 突然有个 AI 想法 | 创建 `💡 Inbox/想法/AI-xxx.md`，扔进去 |
| 晚上写今日感悟 | 打开今天的 `📓 Daily/`，写在「随记」里 |
| 刷到一篇好文章 | 创建 `📚 材料/待读/小红书-xxx.md`，贴链接 |
| 周五整理时间 | 读一篇待读 → 移到已读 → 写总结 → 链接到相关想法 |
| 月底回顾 | 看看 MOC，更新索引 |
